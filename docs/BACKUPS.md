# CETI Database Backups

This document describes the CETI database backup setup so it can be reconstructed later.

## Backup design

The CETI validator keeps certificate data in MariaDB. PDFs are not part of the long-term backup/archive design.

The backup flow is:

1. MariaDB database running in Docker.
2. `/root/ceti-backups/backup-db.sh` creates a compressed SQL dump.
3. The script verifies gzip integrity.
4. The script verifies that the `certificados` table is present in the dump.
5. Only a verified dump is promoted to a local `.sql.gz` backup.
6. The verified backup is copied off-server to Google Drive with rclone.
7. `rclone check` verifies the Google Drive copy against the local backup.
8. Local database backups older than 30 days are deleted.

## Current backup script

```bash
#!/bin/bash
set -euo pipefail

BACKUP_DIR="/root/ceti-backups"
CONTAINER="dkfgkwggxveg2jwljtxwmeug"
REMOTE="ceti-google-drive:CETI-Backups/Database"

DATE=$(date +"%Y-%m-%d_%H-%M-%S")
BACKUP="$BACKUP_DIR/ceti-db-$DATE.sql.gz"
TEMP="$BACKUP.tmp"

echo "Starting CETI database backup..."

docker exec "$CONTAINER" sh -c \
  'mariadb-dump -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"' \
  | gzip > "$TEMP"

gzip -t "$TEMP"

if ! gzip -cd "$TEMP" | grep -q 'Table structure for table `certificados`'; then
    echo "ERROR: certificados table not found in backup."
    rm -f "$TEMP"
    exit 1
fi

mv "$TEMP" "$BACKUP"

echo "LOCAL BACKUP VERIFIED"
echo "File: $BACKUP"
echo "Size: $(du -h "$BACKUP" | cut -f1)"

echo "Uploading to Google Drive..."
rclone copy "$BACKUP" "$REMOTE/"

echo "Verifying Google Drive backup..."

if rclone check "$BACKUP" "$REMOTE/" --one-way; then
    echo "GOOGLE DRIVE BACKUP VERIFIED"
else
    echo "ERROR: Google Drive backup verification failed."
    exit 1
fi

find "$BACKUP_DIR" \
  -name "ceti-db-*.sql.gz" \
  -mtime +30 \
  -delete

echo "CETI BACKUP COMPLETE"
```

## rclone Google Drive configuration

rclone is installed on the Hetzner server. The Google Drive remote was created with:

```bash
rclone config
```

Configuration choices used:

- Remote name: `ceti-google-drive`
- Storage type: Google Drive
- OAuth client ID: default/blank during the initial setup
- OAuth client secret: blank
- Scope: `drive.file` (rclone-created files)
- Service account file: blank
- Advanced config: No
- Auto config on the headless Hetzner server: No
- Authorization was completed on a browser-equipped Mac using the `rclone authorize` command generated by the server.
- Shared Drive / Team Drive: No

To verify the configured destination:

```bash
rclone ls ceti-google-drive:CETI-Backups/Database/
```

To verify a local backup against Google Drive:

```bash
rclone check /root/ceti-backups/<backup-file>.sql.gz ceti-google-drive:CETI-Backups/Database/ --one-way
```

## Reconstructing rclone on a new server

Do **not** copy credentials into Git. On a replacement server:

1. Install rclone.
2. Run `rclone config`.
3. Create a Google Drive remote named `ceti-google-drive`.
4. Use `drive.file` scope unless the requirements change.
5. Complete OAuth authorization interactively on a trusted computer with a browser.
6. Confirm access with `rclone ls ceti-google-drive:CETI-Backups/Database/`.
7. Install the backup script at `/root/ceti-backups/backup-db.sh` and make it executable (`chmod 700`).
8. Add the cron entry shown above.
9. Run the script manually once and require `LOCAL BACKUP VERIFIED`, `GOOGLE DRIVE BACKUP VERIFIED`, and `CETI BACKUP COMPLETE` before relying on cron.

## Restore / validation notes

A backup is not considered valid merely because a file exists. The backup process intentionally checks the SQL dump before upload and compares the uploaded Google Drive object against the local file.

Before restoring a backup, inspect it first:

```bash
gzip -t /path/to/ceti-db-YYYY-MM-DD_HH-MM-SS.sql.gz
gzip -cd /path/to/ceti-db-YYYY-MM-DD_HH-MM-SS.sql.gz | grep 'Table structure for table `certificados`'
```

A known test during setup confirmed that a dump contained the certificate record `CETI-TR-2026-G2401`.

## Secrets and files that must NOT be committed

Never commit any of the following:

- rclone OAuth access/refresh tokens
- the actual rclone configuration containing credentials (normally under the root user's rclone config directory; determine the active path with `rclone config file`)
- Google OAuth client secrets
- MariaDB passwords
- Vault AppRole Role ID / Secret ID or Vault unseal keys
- Coolify API tokens
- application admin passwords
- any `.env` or other file containing live credentials

The repository should document **how to recreate credentials**, not store the credential values themselves.
